Throughout this course, I learned that creating usable and secure software requires more than just writing code that works. Testing is a big part of development because it helps reveal errors and it also makes sure the program satisfies its requirements. In the Contact Service project, I used JUnit tests to verify that contacts could be created, updated and removed the right way. I also tested invalid scenarios, for example when the information was wrong or missing, so the application behaved properly in those edge cases. Working through these tests helped me understand the importance of testing both normal and unexpected situations. I also learned that software quality and security should be considered throughout development rather than only after the program has been completed.

Understanding user needs is another important part of creating effective software. I learned that requirements give a foundation for figuring out what a program should do and how it should behave. For the projects in this course, I relied on the provided requirements to decide what information each service needed to keep and what users should be able to do. After that I used those same requirements when making my code and also when building my tests. By tying requirements to the actual functionality and testing, I could be more sure that the software matched the real intended needs rather than just writing code with no clear direction.

When I design software, I usually take the problem and split it into smaller parts. Working with separate classes and services made it easier to zoom in on individual responsibilities instead of trying to assemble everything at once. I also noticed that considering the requirements first before writing any code made the whole process more organized. Testing each part as I went along helped me identify issues earlier. Overall this course taught me that good software development involves understanding the requirements, putting together organized components, writing the implementation and then keeping an eye on the results through continuous testing. I think these habits will help me face future programming work in a more structured and dependable way.
